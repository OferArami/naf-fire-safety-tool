# צינור עדכון הנתונים — "בונה תוכנית בטיחות אש"

מושך מחדש את מאגר הדרישות מ-gov.il ("שלהבת") ובונה קובץ HTML מעודכן, בלי לגעת
בשום דבר אחר בכלי (עיצוב, מחשבונים, תיקוני הבאגים) — נוגע **רק** בבלוק ה-DATA.

## חשוב לדעת לפני שמריצים

זו **קריאה ל-API לא-רשמי ולא-מתועד** של gov.il, שגילינו יחד ע"י בדיקת תעבורת
הרשת בדפדפן — לא API ציבורי מתועד.

**עדכון מהריצה בפועל**: gov.il יושב מאחורי **Cloudflare עם אתגר אנטי-בוט**
("Just a moment..." + `Server: cloudflare`) — קליינט Python רגיל (גם עם
Session/עוגיות/כותרות browser-like) נחסם עם 403 על **כל** נתיב תחת
`gov.il/api/kabaut/shalhevet/*` — כולל עצי הקטגוריות וגם רשימת הדרישות.
**לא ננסה לעקוף את זה**. לכן: **דלגו לגמרי על `01_fetch_trees.py` ו-
`02_fetch_requirements.py`** — שניהם קוראים לאותו דומיין חסום ולא צפויים
לעבוד. כל התהליך רץ מ-`browser_console_fetch.js` בלבד (שלב אחד בדפדפן,
כולל את שני העצים וגם את כל הדרישות), ואז `02b_import_browser_export.py`
ממיר את הפלט שלו לקבצים ש-`03_build_data.py` מצפה להם.

- הסקריפט בדפדפן מריץ בקשה **אחת בכל פעם**, עם השהיה של שנייה בין בקשה לבקשה.
- שומר התקדמות (`IndexedDB`) — אם הלשונית נסגרת/קורסת באמצע, מריצים שוב והוא ממשיך מאיפה שנעצר.
- **אני (Claude) לא יכול להריץ שום דבר מזה בעצמי** — הסביבה שלי לא מגיעה ל-gov.il ואין לה דפדפן. אתה (או השותף שלך) צריכים להריץ את זה בפועל.

## התקנה (פעם אחת)

```bash
pip install -r requirements.txt
```

## הרצה — בפועל 3 שלבים (לא 5 — ראו "חשוב לדעת" למעלה)

### שלב 1+2 ביחד — משיכת כל הנתונים, מהדפדפן

1. פתחו בדפדפן: `https://www.gov.il/apps/Kabaut/Shalhevet/treeView/?mainCatId=1`
2. `F12` → טאב **Console**
3. פתחו את `browser_console_fetch.js`, העתיקו את כל התוכן, הדביקו בקונסול, Enter
4. חכו ל-"Done!" (~15-20 דקות) — 3 קבצים יורדים אוטומטית ל-Downloads:
   `tree_permit.json`, `tree_business.json`, `requirements_by_leaf.json`
5. העבירו את שלושת הקבצים לתוך התיקייה `update_pipeline/browser_export/`

```bash
python 02b_import_browser_export.py   # ממיר את הפלט של הדפדפן לקבצי cache/
python 03_build_data.py               # בונה 97 קבצי JSON נפרדים (אחד לכל קבוצה) ב-output/site/data/
python 04_inject_html.py              # בונה output/site/index.html שמצביע אליהם
```

התוצאה: תיקיית **`output/site/`** מלאה (`index.html` + `data/`) — זה **כל** מה שהאתר צריך.

## פרסום עדכון — 3 צעדים אחרי שהריצו את הצינור למעלה

1. **פתחו את תיקיית הריפו המקומית** שלכם (זו ששוכפלה עם GitHub Desktop).
2. **העתיקו** את **כל התוכן** מתוך `update_pipeline/output/site/` (גם `index.html` וגם תיקיית `data/`) לתוך תיקיית הריפו — מחליפים את מה שהיה שם.
3. **פתחו את GitHub Desktop** — הוא יראה את כל הקבצים ששונו. לחצו **Commit to main**, ואז **Push origin**. תוך דקה, האתר החי מתעדכן לכולם.

**חשוב**: אין יותר קובץ HTML בודד שמכיל את כל הנתונים — האתר טוען רק את הקבוצה שנבחרה, לא הכל בבת אחת. זה הפתרון לבעיית-הזיכרון/הקריסות שדווחו בגרסה הישנה.

### שלב אופציונלי — לפני שמפיצים, לראות מה בדיוק השתנה
`05_diff_report.py` (השוואה מול קובץ HTML בודד) **לא מתאים יותר** למבנה החדש
(97 קבצים, לא קובץ אחד) — לא עודכן עדיין. לבינתיים, הדרך לראות מה השתנה היא
`git diff` בתוך GitHub Desktop לפני ה-Commit — הוא מציג בדיוק אילו קבצים
נוספו/הוסרו/השתנו בכל עדכון.

## איך זה עובד (בקצרה)

1. **`browser_console_fetch.js`** רץ בתוך הדפדפן שלכם (לא Python) ומושך הכל:
   קודם את שני עצי הקטגוריות (מסלול היתר-בנייה ומסלול רישוי-עסקים — כ-700-900
   קטגוריות בסה"כ, כולל אלו שאינן "עלים"), ואז מחשב אילו קטגוריות הן עלים
   (אין להן קטגוריות-בת) ומושך לכל אחת מהן את רשימת הדרישות המלאה. תגלית
   מפתח שבדקנו יחד: קריאה לעלה מחזירה **גם** את כל הדרישות שחלות על ההורים
   שלו לאורך הנתיב מהשורש — לכן מספיק לקרוא לעלים בלבד (ראו את הדיון בשיחה
   למעלה).
2. **`02b_import_browser_export.py`** מציב את 3 הקבצים שהדפדפן הוריד באותו
   מבנה תיקיות ש-`03_build_data.py` מצפה לו.
3. **`03_build_data.py`** (הלוגיקה ב-`transform.py`) בונה את כל הדרישות
   בפורמט הפנימי (כולל שחזור נכון של "שורות כלליות" — דרישה שמעוגנת
   בקטגוריית-אב וחלה על כל הצאצאים שלה), ואז **מפצל** אותן ל-**97 קבצי JSON
   נפרדים** תחת `output/site/data/` — קובץ אחד לכל קבוצה, עצמאי לגמרי
   (כולל מאגר-המחרוזות הפרטי שלו), כך שהאתר יכול למשוך רק אותו בלי כלום אחר.
4. **`04_inject_html.py`** בונה את `output/site/index.html` מתוך `site_template.html`
   (העיצוב, המחשבונים, הלוגיקה — קבועים) ומשתיל רק שני דברים קטנים: רשימת
   97 הקבוצות (לתפריט הבחירה), ומפה שאומרת לכל קבוצה איפה קובץ-הנתונים שלה.

## קבצים

| קובץ | תפקיד |
|---|---|
| `common.py` | קבועים משותפים — כתובות ה-API, נתיבי קבצים, הגדרות קצב-בקשות |
| `transform.py` | הלוגיקה הטהורה שהופכת עץ-קטגוריות + דרישות לשורות-נתונים — נבדקה מול נתונים אמיתיים ב-`test_transform.py` |
| `test_transform.py` | בדיקות תקינות מול דוגמאות אמיתיות מה-API (לא צריך אינטרנט להריץ) |
| `site_template.html` | תבנית האתר (עיצוב + מחשבונים + לוגיקה) — **בלי** שום נתוני-דרישות בפנים |
| `browser_console_fetch.js` | **שלב 1 בפועל** — רץ בתוך DevTools Console, מושך הכל (עצים + דרישות) כי Cloudflare חוסם Python לגמרי על הדומיין הזה |
| `02b_import_browser_export.py` | **שלב 2 בפועל** — ממיר את 3 הקבצים שהורדתם מהדפדפן לאותו מבנה קבצים שהצינור מצפה לו |
| `01_fetch_trees.py`, `02_fetch_requirements.py` | גרסאות Python-טהור — **לא צפויות לעבוד** (חסומות ע"י Cloudflare על אותו דומיין), נשמרו כתיעוד/לעתיד אם ההגנה תשתנה |
| `03_build_data.py` — `04_inject_html.py` | בונה ומשתיל — זהה, לא משנה איזה משני הנתיבים הביא את הנתונים |
| `05_diff_report.py` | השוואת גרסה ישנה מול חדשה (אופציונלי) |
| `samples/` | קטעי JSON אמיתיים ששימשו לבדיקת `transform.py` |
| `cache/` | כאן נשמרים כל הקבצים שנמשכים מהרשת (נוצר אוטומטית) |
| `output/` | כאן נכתבים כל התוצרים (נוצר אוטומטית) |

## אם משהו משתבש

- **"Just a moment..." / status 403 עם `Server: cloudflare`**: זו לא שגיאה
  שצריך "לתקן" — זהו אתגר אנטי-בוט שקליינט Python לא יכול לעבור. עברו לנתיב
  הדפדפן (`browser_console_fetch.js` + `02b_import_browser_export.py`) — זה
  בדיוק המקרה שהוא נועד לפתור.
- **שגיאת רשת/timeout באמצע `02_fetch_requirements.py` (או קטגוריה בודדת
  שנכשלה בתוך `browser_console_fetch.js`)**: פשוט הריצו שוב את אותה פקודה —
  היא תדלג על מה שכבר נשמר ותמשיך מאיפה שנעצרה (גם ב-Python וגם בדפדפן,
  דרך `IndexedDB` — ראו את הערך הבא).
- **`QuotaExceededError` בדפדפן**: קרה בגרסה קודמת של `browser_console_fetch.js`
  שהשתמשה ב-`localStorage` (מוגבל לכמה MB בודדים) — עם מאגר בגודל הזה זה נגמר
  מהר. הגרסה הנוכחית עברה ל-`IndexedDB` (מכסה גדולה בהרבה, בדיוק בשביל זה).
  אם עדיין רואים את השגיאה, ודאו שאתם משתמשים בגרסה העדכנית של הקובץ.
- **קטגוריה עם יותר מ-4 רמות-משנה**: `transform.py` יזרוק שגיאה ברורה במקום
  לקטוע נתונים בשקט. אם זה קורה, זה אומר שהמבנה של gov.il התעמק מעבר למה
  שהכלי תומך בו כרגע — צריך להרחיב את מערך `LEVELS` בקוד ה-JS של הכלי עצמו
  (`script_3.js`) ולא רק כאן.
- **`site_template.html` שונה או אבד את סימן ה-placeholder**: `04_inject_html.py` יעצור
  עם שגיאה ברורה (`Could not find the marker`) במקום להשתיל במקום הלא-נכון.

## עדכון מ-data.gov.il (הדרך המומלצת והמעודכנת)

רשות הכבאות מפרסמת את הדרישות כנתונים פתוחים, מתעדכנים חודשית:
- היתרי בניה: https://data.gov.il/he/datasets/firefightingcommission/prvbuildingquirement
- רישוי עסקים: https://data.gov.il/he/datasets/firefightingcommission/businessreq

שלבים:
1. היכנס ל-data.gov.il, פתח Console (F12) והדבק את `opendata_download.js`. הסקריפט מאתר לבד את הקובץ החודשי העדכני ביותר ("נכון ליום ...") ומוריד `permit.json`, `business.json` ו-`opendata_meta.json`.
   חשוב: במאגר יש קובץ נפרד לכל חודש. אין להשתמש במזהה קובץ קבוע — הוא נשאר על חודש ישן.
2. העתק את שלושת הקבצים לתיקייה `opendata/` ובדוק ב-`opendata_meta.json` שהתאריך הוא החודש האחרון.
3. `python3 03b_build_from_opendata.py`
4. `python3 04_inject_html.py`
5. תוצאה מוכנה ב-`output/site/` (index.html + data/). העתק לתיקיית ה-repo, ואז Commit ו-Push ב-GitHub Desktop.

הערות: שורות עם עמודת מקור "שבורה" (3 שורות ברישוי עסקים) מתוקנות אוטומטית ומדווחות ב-`output/build_report.json`.
דרך הגרידה הישנה (01–03) חסומה כרגע על ידי Cloudflare ולא נדרשת יותר.
